# 这一路到底是怎么查的

这篇按“看到什么 → 怎么判断 → 试了什么 → 结果怎样”来写。主要依据是当时的聊天记录、留下来的脚本和打包报告。没有原始日志的地方就写成排查摘要，不凑假的 logcat。

## 1. 桌面进不去，设置点几下也会崩

**看到的情况：** 设置首页能打开，但继续点“我的设备”、滚动或返回会出问题；原生桌面进程起来了，也不一定能画出第一帧。

**当时怎么查：** 把“进程有没有起来”和“渲染有没有跑通”分开看。设置交互崩溃指向渲染线程；桌面首帧还卡在 Flutter 的 GLES 路径。

**试过的东西：** 暂时关闭部分模糊和动画，处理 spawner 的路径兼容，再查 GLES 首帧。关闭效果只能算绕过，没把它写成最终修好。

**踩过的坑：** 一次触摸监测库试验后，保存的日志摘要出现 `surfaceflinger exited, code 132`。这说明画面合成服务已经退了，继续等没用；先回退最近的可疑修改，再查崩溃。没有把减少几条日志当作成功。

后面复测能进原生桌面、滑动、打开设置再回来，才算这一段基本跑通。

## 2. 不崩了，但图标还是一块黑

**看到的情况：** 桌面能滑了，图标却黑着。中间处理过重复 Flutter 库加载、FP16 shader 编译和离屏纹理格式，几条绘图报错已经消失，黑块却还在。

**接着怎么查：** 问题不一定在报错最多的地方。下一步要分清：图标生成时就黑了，还是上传到 GLES 以后才坏。后来修到了纹理上传/同步这条链路，普通图标逐步恢复。

**怎么验证：** 除了看一次截图，还要试滑动、进设置再返回和重启。普通图标恢复后，时钟、日历仍有问题，它们走的是另一条动态图标路径，最后保留了静态兼容预览。

## 3. 网页闪退、声音也不对

这两个问题没有直接归到“ROM 太新”上，而是继续查基础服务。

- **WebView：** 历史记录指向共享内存缺少大小封印，以及字体配置断链。处理后冷启动再看浏览器网页、商店首页和网页浮层。
- **声音：** 音量和扬声器路由看着正常，实际播放时音频服务还是会出问题。后来查到共享内存分配服务没启动，补上启动配置后重启，播放由本人确认能听到。
- **视频黑屏：** 后来还做过 YUV→RGB 的 GLES 兼容处理，再让视频持续播放验证，没有拿一张正常首帧就宣布完成。

这里也有个经验：开关没静音，不代表音频链路就真的通了。

## 4. AE 有“来电”按钮，ROM 却不认

**看到的情况：** AE 模拟信号已经开了，系统却不认虚拟 SIM，点来电也没反应。

**找到的线索：** ROM 的电话框架不再接受 AE 提供的旧接口，历史错误摘要提到不支持低于 IRadio 1.4 的版本。所以改信号图标或者运营商名字没用，接口没有接起来。

**最后怎么做：** 在 ROM 里加桥接服务，把新电话框架和 AE 原有模拟通道接上。依次看信号、响铃、接听、挂断，重启后再试。没有改 AE APK，也没有碰宿主的真实 SIM。

**后面漏过一次：** 电话通了不代表短信也通。短信收不到时继续查事件，发现桥接漏接新短信事件，补上投递和确认后才收到。

## 5. 有铃声文件，选了却不按新铃声响

**看到的情况：** 不是把一个音频文件复制进去就结束，选择器和系统设置还需要正确的媒体索引。

**当时的判断：** 把文件是否存在、MediaStore 是否登记、设置里的铃声 URI 分开查。MediaProvider 扫描后，选择器能写入选中的 URI，最后再用模拟来电确认听到新铃声。

**放进新包时：** 不能把旧实例数据库直接拷过去。R3 改成首次启动正常扫描系统铃声/通知/闹钟，全部扫描成功才写完成标记；失败就留着下次再试，后续开机也不重置用户选过的铃声。

## 6. 分辨率、DPI 和原生界面比例对不上

**这里有过误判：** 一次 ADB 查询拿到的是 K80 宿主参数，不能拿来当 AE 虚拟系统的数据。确认连接对象后，才重新查虚拟系统的画面几何和密度。

**最后的做法：** AE 实例手动设成 1080×2160 / 403 DPI，再同步 MIUI 面板参数、原生自动密度和 Android 逻辑密度。第一次初始化完要正常重启一次。

**也有没用的尝试：** 来电背景块状问题试过把 HWUI 比例候选从 25% 调到 50%，冷启动对比看不出改善，所以清掉临时设置，没有硬留在最终包里。

**另一个容易误会的点：** 往包里放 JSON 不会让 AE 0.0.0.3 自动照着设置实例分辨率，所以使用说明里仍然让人手动填。

## 7. 天气装不上，浏览器更新也卡住

这两个放一起看很像，但实际不是同一个问题。

- **天气等应用：** 运行库文件在，但缺少匹配的 shared-library 声明。补上 v3/v5 和 `miui-uninstall-empty.jar` 注册后，再检查安装与启动。
- **浏览器：** 旧预置 APK 和商店版本有签名冲突。旧包移出扫描位置并备份，再用原签名版本；不靠取消系统签名校验解决。

浏览器安装有本人确认成功。库声明补全也不等于所有应用的每个功能都测过，文档只记已经确认的部分。

## 想复查时，可以从哪看

下面是这次整理的检查入口，**请在 AE 虚拟系统的 shell 里运行**。它们不是当时原始输出的逐行回放，本次公开整理也没有重新连手机执行：

```sh
# 先确认查的是谁，再看显示参数
getprop ro.product.model
wm size
wm density
getprop qemu.sf.lcd_density
getprop persist.sys.miui_resolution

# 已经装没装上、声明是什么
pm path com.miui.weather2
dumpsys package com.miui.weather2

# 音频、电话和第一轮启动记录
dumpsys media.audio_flinger
dumpsys telephony.registry
cat /data/local/tmp/ae-hyos/first-boot.log
```

最后这一步也补上了：除了 ZIP 完整性检查，R3 后来又在 **K80、Neo11** 上分别做了导入测试，两台都能运行。这个结果是我在 10 月 24 日补充确认的，不是拿早期集成包的结果来顶。
