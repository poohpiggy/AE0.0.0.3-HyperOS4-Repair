# 从 GLES 实验包到 R3

以下日期使用 UTC+8，根据历史对话和保留构建文件整理。早期临时文件已清理；无法回溯的实现不补写成“原始源码”。

## 1. 明确运行边界（10 月 21 日）

目标是红米 K80 上的 **AE 0.0.0.3 虚拟机**，运行 HyperOS 4 / MIX2S 客体，保留原生小米桌面，只走 OpenGL ES。不是将 MIX2S 固件刷入 K80，也不是修改真实基带。

早期先产出 MIX2S / MIX3 的 GLES 实验包，通过文件系统和 ZIP 检查；当时尚未实测，不能将“包生成成功”当作“系统运行正常”。

## 2. 原生桌面、缩放与图形链路（10 月 21—22 日）

设置首页能显示，但继续点击会触发渲染线程崩溃。关闭部分模糊和动画只是一度可用的绕过方案。修复过程中处理 spawner 的路径兼容、触摸连接阻塞、重复运行库加载和纹理上传同步等问题，随后用滑动桌面、打开设置再返回和重启复测。

有一次触摸监测库试验后 SurfaceFlinger 退出，记录将它列为优先回退项；没有把这次试验算成修复成果。普通图标黑块逐步恢复后，时钟与日历的独立动态图标路径仍有异常。

## 3. WebView、音频与模拟电话（10 月 22 日）

WebView 故障涉及共享内存大小封印及字体配置；音频故障涉及共享内存分配服务未启动。历史记录包含浏览器/商店启动复测，以及作者确认播放声音正常。

电话框架拒绝旧 Radio 接口，因此在 ROM 内加入模拟基带桥接，连接 AE 既有信号、来电按钮、接听和挂断。随后发现桥接遗漏新短信事件，补齐投递与接收确认。该链路是虚拟 SIM/信号/来电/短信，不能推导真实蜂窝网络能力。

这一阶段的 MIX2S 集成包有过全新导入验证；该结论只属于当时包体，**不能自动迁移到后来的 R3 新 ZIP**。MIX3 按当时要求未实测。

## 4. R2 合并及体积压缩（10 月 22—23 日）

集成 GLES、音频、模拟电话/短信、WebView、启动持久化及日志降噪等已保留改动。补虚拟充电节点、对指定高频日志做窄范围过滤；没有把所有错误日志直接屏蔽。

动态图标暂用静态兼容预览。液态玻璃及动态图标路径没有完整修好。曾使用 tar.xz 比较无损压缩体积，之后维护者明确选择 ZIP 格式。

## 5. R3：铃声、1080p / 403 DPI 与应用安装（10 月 23—24 日）

当前实例里，铃声文件存在不等于已登记到媒体库；通过 MediaProvider 索引后，铃声选择器能够记录所选项，作者确认听到新铃声。

显示检查曾误把宿主屏幕尺寸当成客体参数，后改用客体身份与几何节点确认。最终将实例配置固定为 1080×2160 / 403 DPI，同时处理逻辑密度与 MIUI 原生密度一致性。AE 导入器不依据额外 JSON 自动设置该参数，因此说明要求导入后手动设置实例。

天气安装缺失库声明，浏览器则有旧预置包签名冲突。分别补真实库注册和替换预置扫描位置，不采用取消系统签名验证的方式。浏览器安装由维护者确认成功。

## 6. 归档与公开整理（10 月 24 日）

构建基于当时 R2 包，合入 R3 payload，输出 ZIP Deflate level 9 / ZIP64。构建日志记录 system/vendor 文件系统检查通过，以及全部 ZIP 成员的大小、SHA-256 和 CRC 校验。旧构建镜像与旧包随后清理，只保留最终 ZIP、说明、清单、少量脚本及报告。

现在按主题整理为多个 commits：范围与署名 → 启动/密度 → 应用库注册 → 打包与核验 → 验证依据 → Release 分卷与修改日志。commit 时间是本次整理时间，没有倒填调试日期。
