# 开机修复和显示比例

## 为什么不能只改 build.prop

AE 0.0.0.3 的实例分辨率/DPI 由实例设置控制。包里写 1080×2160/403，或者附带 `AE-INTEGRATED.json`，不会强制导入器选用这套实例参数。

R3 的处理分三层：

1. 用户在 AE 设置选择 **1080×2160 / 403 DPI**。
2. `start-spawner.sh` 读取客体 `/dhd.fbgeom` 和 `qemu.sf.lcd_density`，同步 MIUI 面板元数据；原生自动密度的比例计算来自当时该实例的调试结果，不当作所有 ROM 的通用公式。
3. `settings.sh` 在客体启动完成后执行 `wm density`，让 Android 逻辑密度一致。首次初始化完成后再正常重启一次。

## 启动脚本

- `start-spawner.sh`：从系统内的兼容目录恢复运行文件，并在 AE 注入 stock GLES 驱动后安装已集成的兼容驱动；启动 spawner。
- `settings.sh`：等待 `sys.boot_completed`；默认设置仅首次应用；缺失的天气/主题应用尝试补装；建立系统音频索引。

启动脚本依赖基包里已有的原生库及 spawner 二进制。本仓库没有这些第三方运行文件；只复制本仓库的 shell 文件到任意 Android 系统不能构成完整修复。

## 铃声索引的完成标记

扫描铃声、通知、闹钟目录。只有扫描未报错且至少处理一个文件后，才写 `builtin-audio-indexed-r3`。失败会保留重试机会，后续正常启动不会覆盖用户选择的铃声或拷贝旧实例的媒体数据库。

默认初始化仍会设置首次配置项；这是 R3 保留的实际行为，不声称首次启动“完全不改设置”。
