# 这一轮：看着好了，还得新导入试一下

这一轮从旧包继续改，没有换 AE 版本，还是 **AE 0.0.0.3**。内部记过 R4、R4.1，下面说的是这个过程，不是多个下载版本。

## 多任务卡片为什么空白

先查组件配置，发现需要把系统的 Recents 指向原生桌面里的 `com.miui.home.recents.RecentsActivity`。做成了一个小资源 overlay，再重启看设置和浏览器卡片，也点回浏览器确认不是只有一个空框。

仓库里保留了 overlay 的 Manifest、资源 XML 和当时编译的小 APK。签名私钥不上传。

## 浏览器安装好了，第一次开又闪退

上次解决的是旧预置包和商店版签名冲突。这次发现又是另一层：应用装进系统目录后，APK 里的原生库没有按预置应用需要的目录准备好。

把同一个官方 APK 里 `lib/arm64-v8a/` 的 **66 个 `.so`** 展开到它自己的 `lib/arm64/`，逐个比对字节哈希。之后做冷启动和重启复测，记录里有 1281 ms 的冷启动；后面的干净导入候选里还有一次 1227 ms，没出现新的应用崩溃记录。

这说明启动问题跑通了，但浏览器桌面/多任务标题图标仍可能黑块，没有顺带写成图标也全好了。

## 图标再整理一下

移开旧 dynamicicons，静态主题配置关掉 dynamic/layer 路径。日历和时钟做了圆角透明边，以及 1.45 倍居中放大。仅靠 PNG 检查只能确认大小和 alpha，不能判断文字有没有被裁，所以后来也看了真实桌面画面。

日历显示的是固定日期，时钟指针也是固定的，不会走时。天气、日历和时钟的兼容显示通过，不代表所有图标问题都解决。

## 明明 wm 尺寸对，画面怎么还是缩了

这是这轮比较容易看错的地方。`wm size` 正常，实际合成缓冲区却还沿用旧尺寸，所以外层会缩小或裁切。

原来在 spawner 才同步显示参数，已经晚了。后来改到 **SurfaceFlinger 执行前**，从 `/dhd.fbgeom` 和 AE 的密度属性同步，顺便清掉旧的 forcedWidth/forcedHeight，只更新本地显示，不改其他显示配置。

两个启动入口都走同一个包装脚本。代码审查还抓到过一次问题：用过短的 init 模板覆盖原文件，会漏掉 `onrestart`、`writepid` 和属性触发器。当前打进去的文件保留了这些行，不是那份 7 行临时模板。

720×1280 / 320 和 1080×2160 / 403 做了双向切换，`wm`、framebufferSpace、RenderSurface 都对上，外层等比。这是改参数后的下次启动生效，不是运行中热切换。

## 新导入才暴露的铃声漏项

在原来的实例里补齐音频后看着正常，干净导入才发现：`sys.boot_completed=1` 不代表 MediaProvider 已经能查询。早期日志里确实有 Provider 不可用；后面查到 56 条完整记录，是补修后的结果，不能反过来说原包首启就没问题。

所以又加了一步：先查询真实的 `content://media/internal/audio/media`，确认能返回结果再扫文件；等待超时不写成功标记，下次启动还能重试。

然后重新打包，再新建一个实例导入。验收时 `bootCount=1`，首启直接登记了全部 **56 个内置音频**，没有再靠手工补修。用户也确认可以正常使用。这才是这次上传的包。

## 这轮的结果怎么理解

新包的干净导入和首启音频验收通过。浏览器、多任务、图标及两组显示参数的完整检查来自紧邻的候选，最后一次仅增加媒体服务等待逻辑，相关文件哈希也核对过。

新 ZIP 没有再把所有分辨率、来电听感和每个应用功能重跑一遍。哪些测过、哪些没测，见 [测试记录](validation.md)。
