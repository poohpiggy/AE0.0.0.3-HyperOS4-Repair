# HyperOS 4 for AE 0.0.0.3

> 在 **AE 0.0.0.3** 里折腾 HyperOS 4。保留原生桌面，采用 OpenGL ES 路线。

这里记录了我怎么从桌面白屏、图标黑块，一路查到分辨率、多任务、浏览器和铃声初始化。能找到的修复脚本、资源补丁、打包工具和验证记录都放在这里。

**只用于 AE 虚拟机导入，不给实体手机刷机，也不修改宿主系统或 AE APK。**

[下载适配包](https://github.com/poohpiggy/AE0.0.0.3-HyperOS4-Repair/releases/tag/hyperos4-ae0.0.0.3) · [怎么导入](docs/import-guide.md) · [怎么查错的](docs/troubleshooting.md) · [这一轮改了什么](docs/latest-repairs.md) · [修改日志](CHANGELOG.md) · [测试记录](docs/validation.md)

## 这次又修了什么

- **改分辨率后不用再手动补显示参数。** 在 SurfaceFlinger 启动前同步 AE 宽高和 DPI，清掉旧的强制宽高。已经测过 720×1280 / 320 与 1080×2160 / 403 双向切换；改完要重启实例，不是热切换。
- **多任务卡片能看到预览。** 补了正确的 Recents 组件配置，设置和浏览器卡片、点回浏览器都做过复测。
- **浏览器第一次启动缺库闪退。** 把官方 APK 里的 66 个 ARM64 库按系统预置应用的目录展开，逐个比对哈希，没有改签名验证。
- **静态图标再整理了一下。** 天气、日历和时钟按兼容样式显示，日历/时钟做了圆角和居中放大。它们是固定预览，日期和指针不会实时更新。
- **新导入时铃声不再漏登记。** 这次真的用新实例导入，发现开机完成时媒体服务还没就绪。改成等待真实 Provider 后再扫描，新包第 1 次启动自动登记了全部 **56 个内置音频**。

前面做过的 GLES、WebView、音频、模拟来电/短信、天气依赖注册等改动都保留。过程里走过的弯路也写在文档里，不只列成功结果。

## 还没搞定的地方

液态玻璃、部分图标黑块、安全中心启动异常还在。日历/时钟现在是静态兼容方案，不当作动态图标已经修好。新包没有再次穷举所有分辨率，也没重新听一次实际模拟来电铃声。

## 仓库里有什么

```text
payload/       要放进系统镜像的 shell、init 配置和库声明
assets/        小体积多任务 overlay、静态主题补丁
overlay/      多任务 overlay 的资源源码
manifests/     当前包、分卷清单，以及历史构建资料
reports/       构建检查、导入验收和发布校验
tools/        打包、归档核验、分卷合并工具
tests/        离线测试，不连接手机
docs/         折腾经过、排错和使用说明
```

完整 ROM、商店 APK、用户数据和签名私钥不进 Git。早期原生兼容库有部分源码已经没有保留，因此仓库不是从原厂 ROM 一键重建的完整工程。当前构建方法见 [构建说明](docs/build.md)。

制作时的 R2、R3、R4、R4.1 只是内部阶段名，放在过程回顾里；对外名称一直是 **HyperOS 4 for AE 0.0.0.3**，不加“最终”或“完美”标签。commits 是按实际改动补整理的，使用整理时的真实时间。
